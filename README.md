# OrderCore-OS-Driven-Scheduling-and-DBMS-Backed-Resource-Management-for-Food-Delivery

When you order food online, a lot happens in the background that most people never think about — the restaurant has to start preparing your order, an agent has to be found and assigned to deliver it, and this same thing is happening for dozens of other orders at the exact same moment. If a platform doesn't manage this properly, orders start piling up and delivery feels slow and unreliable. That's basically an Operating Systems problem hiding inside a food app.
In this project, we're treating orders as processes, delivery agents as limited resources, and restaurant preparation as the task that actually "executes" them. We're scheduling orders using FCFS, SJF, and Priority Scheduling, and comparing how each one performs using waiting time and turnaround time. Since multiple orders need to be handled at once, we're using multithreading, and to stop things like two people ordering the last item at the same time, we're handling synchronization with mutex locks. We're also purposely creating a deadlock — one order stuck holding a restaurant slot while waiting on an agent, and another order holding that agent while waiting on the restaurant — so we can actually show how to detect and prevent it, instead of just explaining it in theory.
On the database side, we've designed a normalized MySQL schema covering customers, restaurants, food items, orders, order items, delivery agents, and deliveries, with proper keys and constraints. Everything connects through a Node.js/Express backend, with a simple dashboard on top so the whole system is actually visible and usable, not just running in the background.
